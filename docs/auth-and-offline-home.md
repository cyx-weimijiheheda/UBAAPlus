# UBAA 认证与缓存首页移植

参考仓库：BUAASubnet/UBAA，提交 `6c4dba8d136da1c18ed01ebd4daf213a81ea3155`，仅作只读对照。

## WebVPN 图片验证

对照 `crates/ubaa_core/src/auth/automatic.rs`、`interactive.rs`、`captcha.rs` 和 `captcha_image.rs`：

- 并非取消学校验证码，而是在同一 WebVPN Cookie 作用域中本地识别图片。
- 只处理已支持的 image 类型、六位字母数字；最多自动尝试三次，失败交给原人工输入界面。
- 图像答案、图片 ID 和 execution 必须来自同一个准备页；提交前不重新 GET 登录页。
- POST 参数保持 `username/password/captcha/captchaResponse/execution/_eventId/submit/type`。
- 重试只使用已识别的验证码拒绝响应及其下一张挑战；不把超时或其它错误当作识别失败重提。
- Direct 保持人工输入；会话、Cookie、execution 不跨连接模式使用。取消或切换模式后的旧结果不能恢复界面登录态。

复用 UBAA 随仓库的 `common.onnx.gz` 和 `charset.json`，来源为 ddddocr 1.6.1 的 common_old 模型；后续重新量化 LSTM 以减小模型，详见 [OCR 与首页性能](ocr-and-home-performance.md)。
Android 使用 ONNX Runtime 1.23.2 CPU 推理，五像素白边、170×64 灰度归一化输入、CTC 去重解码。
缩放使用本地双线性采样。模型和字符集不含用户验证码，识别完全在本机完成。识别器兼容 aapt 解压并去掉 `.gz` 后缀的 APK 资源，以及保留 gzip 的资源布局；交付时核对打包后模型与源模型解压字节一致。
模型声明及 MIT 许可证见 [ddddocr-MIT.txt](licenses/ddddocr-MIT.txt)，参考工程许可证见 [UBAA-MIT.txt](licenses/UBAA-MIT.txt)。
ONNX Runtime 的 Java 接口依据：[官方文档](https://onnxruntime.ai/docs/get-started/with-java.html)。

## 会话未恢复时显示本机内容

对照 `packages/ubaa_app/lib/src/controller/recovery/startup.dart`、`packages/ubaa_ui/lib/src/features/home/shell_helpers.dart` 和 `packages/ubaa_host/lib/src/app_service.dart`：

- 首屏先按已确认账号显示已保存课表、待办、考勤和座位摘要，后台恢复会话，再增量刷新。今日课程与签到缓存只用于同一天，避免跨天显示昨日课程。
- 升级迁移只接受与本机课表账号匹配的已认证会话身份，不凭已保存的用户名密码推定身份。
- 缓存入口不等于在线认证。网络业务和学校写操作等待有效会话；离线课表可以读取，本地设置和关于页可访问。
- 部分来源更新失败时保留该来源缓存；成功返回空结果时移除旧记录。账号不匹配不读取、不覆盖缓存。
- 主动退出撤销缓存首页入口；不因保留密码而自动恢复该入口。
- 课表和其他日程界面保持原有布局；功能页改动集中在数据来源、缓存优先展示和操作回调。个人中心按隐私展示单独调整。

## 公共更新和公告

与学校认证/连接方式独立。在同意应用声明后启动，并在回到前台时重新检查。
专用公共客户端不携带学校 Token/Cookie，也不会因公共接口 401 而刷新或删除学校会话。
保留成功获取的公共提示供断网时读取；更新缓存按当前客户端版本隔离，成功确认无公告时清除旧公告。

## 后续机制迁移（2026-11-17）

继续对照 UBAA main `6c4dba8d` 的 `features/libbook/schedule.rs`、`facade/judge_refresh/semester.rs`、`controller/recovery/services.dart`、`write/receipt_verifier.dart` 与缓存合同；体育课默认值对照 dev `cc8ebb4f`，不整套引入日程 UI。

- 图书馆使用原始 `date.list` 按日保存 `times/book_start/book_end/book_close`。窗口按北京时间分钟比较，截止分钟仍可预约；缺失窗口拒绝预约，不借用另一日时段。提交前重新读取分区窗口；取消、暂离、完全离开在提交前核对预约状态。迟到的旧日期/分区读取不覆盖当前选择。
- 成绩、考试、SPOC/希冀摘要及详情、博雅已选/详情/统计、个人中心余额使用按账号和精确查询隔离的 AES-GCM 安全存储。Direct/WebVPN 共用内容、会话分离；同查询读取合并。成功空集合替换旧内容，失败保留保存时刻并记录本次失败；缓存不恢复签到资格或一次性座位 query。旧首页明文在启动时迁移或清除。
- 只读认证恢复合并，业务读取最多恢复后再读一次，失败恢复有短时间抑制。账号、路线与本地代次变化拒绝旧结果。离线显示缓存不允许学校写入，博雅写操作会引导登录。
- 图书馆、博雅、课堂签到、研讨室与场地订单接入提交保护。明确的学校回执按原结果处理并发起回读；传输/解析等未知结果只读核对，持久保存按账号与目标哈希隔离的待确认标记。不能证明结果时拒绝再次发送；相似订单、空列表和读取失败不用于证明原操作失败。普通读取可回退缓存，核对写结果禁止回退。底层博雅写请求不再异常重发，图书馆和场地写请求不再重认证后自动重发。
- 希冀只有完整确认整门课程全部为本学期之前的作业，才记为往期；不遇到旧条目即停止，也不再按六个月推定。缺校历、缺时间及跨学期作业继续核实，显式历史读取仍可用。
- 阳光默认值只读取已同步的当前账号、当前学期课表中含「体育」的课程，未知时默认关闭，手动选择始终优先。博雅冲突检查同样只用已同步内容，时间首尾相接不冲突，不完整时明确提示；没有新增自建日程或日程页面。
- 设置页最末「？！！？」开关默认关闭，每次开启先确认免责声明。关闭时隐藏博雅抢课及场地抢单控件，启动入口和发请求前再次检查，正在运行的任务会停止。
- 个人中心头像卡默认显示姓名、学院与学生类型，点击后才显示学号及上游实际返回的联系/证件字段；缺字段显示「未提供」。两张余额卡分别点击眼睛显示，重新进入页面默认遮挡。无新增敏感资料接口。
- 诊断只在本地保留最近 80 条白名单元信息，设置中由用户主动导出，包含版本与 schema。未接入自动遥测，也不导出原始响应、异常原文、URL、堆栈或账号。

上述验证使用合成 DTO、Mock、并发与持久化回归；真实认证、业务写入和 Android 真机观感均需单独验证。本次不执行任何真实预约或选课。

## 非校园网的网费余额

对照 UBAA `crates/ubaa_core/src/features/campus/portal.rs`：余额通过统一门户的 `items?type=personal_data` 动态获取 `net.netFee` 对应 ID，再读取 `detail?id=...` 的 `d.data.value`，不依赖当前 IP 的 `gw.buaa.edu.cn` 在线账号信息。保留旧响应结构兼容，ID 使用 URL 参数编码，零余额正常显示。

门户返回 `e=10013` 或登录 HTML 时，沿当前 Direct/WebVPN 路线及对应 Cookie，最多引导一次门户登录入口，再重读原查询；不在此处提交密码。引导最多十跳，只允许 HTTPS 门户登录/回调/首页和 SSO 登录路径。JSON 请求补齐 XHR 与门户首页 Referer，非零业务错误不会当成成功余额写入缓存。Mock 覆盖 WebVPN 全链路、实际嵌套信封、动态 ID、零值与失败重试上限；尚未使用真实账号在校外网络验证。
