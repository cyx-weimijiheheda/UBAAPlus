# 控件规范审查

范围：本仓库 Compose 界面。下表保留原始审查依据，后续改造已在本地实现，具体见下方完成记录。

本轮已完成：并列单选/多选使用同一栏磨砂分段选择器，保留多选、禁用及取消选择的行为；长选项和大字号自动横向滚动，单选选中项滚入可见区域；已有下拉框不变。

## 建议优先级

| 优先级 | 控件 | 现状举例 | 建议规范 |
|---|---|---|---|
| 高 | 图标按钮 | `SpocAssignmentDetailScreen`、`JudgeAssignmentDetailScreen` 的复制/日历按钮、`FeatureOrderScreen` 排序按钮仍指定 32dp 布局 | 图形 18–24dp，布局槽位至少 48×48dp，同排居中。Compose 可能扩展触控范围，不能因此判定 32dp 图形不可点击，但布局仍应为相邻控件留出空间 |
| 高 | 文本输入与搜索 | `ClassroomQueryScreen` 搜索框为 12dp 圆角，宿舍默认值等输入框为 14dp；字段错误提示未统一 | 共用输入组件，统一 14dp；搜索用搜索图标、清空动作和一致高度。明确输入项的 label、placeholder、keyboardType、IME 动作；校验错误在字段下方显示，网络错误使用页面提示 |
| 高 | 操作层级与等待反馈 | 各页直接组合 Button、OutlinedButton、TextButton；部分操作仅以 Toast 反馈 | 每个操作区一个主要动作；次要操作使用弱化样式，破坏性动作用错误语义色。提交中按钮显示进度并锁定重复点击；禁用原因就近说明 |
| 中 | 弹窗与操作区 | 课程详情、图书馆地图、同伴管理和验证码分别采用 AlertDialog、自定义 Dialog/Surface | 简单确认沿用 AlertDialog；长表单、图片等保留适合的专用容器，共用标题、关闭按钮、滚动区与底部动作规范。确认/取消顺序一致，长文本及大字体不遮住按钮 |
| 中 | 加载、空状态、失败状态 | 已有 `UbaaLoadingState` / `UbaaEmptyState` / `UbaaErrorState`，但成绩、博雅统计、希冀详情等仍直接显示 Text；加载圈也有多种尺寸 | 首次加载、下拉刷新、按钮提交分开处理；共用空状态与错误组件，文案说明下一步，按场景提供刷新/重试。后台刷新时保留已有内容 |
| 中 | 状态标签 | 首页 `TodoChip`、博雅状态及课表颜色各自定义 | 提取 `UbaaStatusBadge`，统一高度、字重、内边距与成功/警告/错误/中性颜色；文字说明状态，不单靠颜色；覆盖深浅模式 |
| 中 | 开关与复选行 | 设置中的开关、场地中的复选项存在不同的行结构 | 标签、说明与控件统一对齐；整行只有一个切换回调和无障碍节点，避免父子重复触发。需要免责声明的开关仍先确认，不能绕过原逻辑 |

## 约束与验证

- 保留现有主题色、深浅模式、液态玻璃导航及磨砂卡片，功能规则与数据更新逻辑不随控件改造改变。
- 优先扩展 `ui/common/components`，避免每页复制一套样式；逐类迁移，区分非交互图标、动作按钮和状态标签。
- 后续装机检查：窄屏、系统字体放大、长课程名、TalkBack、键盘输入、提交中与失败状态。此轮仅完成源码审查和本地构建测试，未做设备侧观感验收。

参考：[Compose 默认无障碍行为](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)、[Compose 弹窗](https://developer.android.com/develop/ui/compose/components/dialog)、[Material 3 组件](https://developer.android.com/develop/ui/compose/designsystems/material3)。

## 后续改造完成记录

- 在 `UbaaControls.kt` 集中提供输入、按钮、图标动作、弹窗、状态、开关/复选行及进度控件；页面使用共用组件，不各自拼一套视觉参数。
- 普通控件圆角 14dp，按钮与图标布局至少 48dp；复制/日历/关闭在课程详情标题区同排对齐。图标动作保留说明并提供长按提示。
- 关闭、取消编辑、完成、刷新、重置与撤销等工具动作图标化，去除与标题关闭重复的普通取消入口；提交、预约、支付及取消预约等业务操作保留明确文字。清理中关闭图标沿用原禁用条件，神秘开关仍每次先确认免责声明。
- 输入框统一到 `UbaaTextField`；搜索支持清空与搜索键，密码支持显示/隐藏；学号/密码/验证码有编辑后必填提示，购电量错误复用原有 `writePower` 判定，联系电话和人数使用对应键盘，不改变请求条件或服务端规则。
- 弹窗统一不透明主题底色、24dp 圆角、标题工具区与关闭图标，正文限制到可用屏高的一部分；已有长内容滚动与图书馆地图专用查看器保留，地图外框同样使用不透明主题底色。
- 提交按钮使用相同进度组件，登录、签到、购电、打卡、研讨室预约及其他已按加载状态禁用的操作增加一致的等待反馈；返回编辑使用次要按钮。只读状态去掉空点击回调，警告、成功与错误颜色适配深浅模式；取消预约/释放座位显示危险操作语义色。
- 设置、主题、登录、场地、打卡和排序筛选中的开关/复选行统一整行点击，子控件不再叠加第二个回调；评教卡片也改为单个复选语义节点，功能排序行因含上下移按钮仍保留独立显示开关并补充说明。
- 成绩、博雅统计、作业详情、评教和签到页面使用共用加载/空状态/错误组件；研讨室状态适配器也委托给同一套布局。小型行内加载与页面加载保留不同尺寸，后台刷新数据保留规则未改。

本轮验证为格式检查、既有三套单元测试、Debug/Release 构建与安装包签名/资源核验；设备侧大字号、TalkBack 和真机观感仍待验收。未推送、未移动版本标签。

## 登录与账户控件修正（2026-11-18）

- 复选框位于文本左侧，开关位于右侧，整行保持单一切换回调；登录只保留记住密码，已保存凭据自动尝试登录。
- 已验证账户先展示本地首页、后台恢复会话；失败通过底部重试提示处理。超时保留会话，只有明确过期才尝试密码登录；仅凭据账户不读取其他账户缓存。
- 退出登录保留本地数据与已记住的密码，并持久暂停自动认证；清除本地数据是另一个需要确认的退出选项。
- 个人信息卡采用左侧 60dp 圆角矩形头像、右侧姓名与标签。未取得官方头像时使用中文姓氏或拉丁名字缩写，手机号等资料仍在点击后的对话框内展示。
- 金额统一按十进制字符串四舍五入到两位小数；校园网流量以 zfw 账户自助页为准，包含套餐可用流量，刷新失败保留缓存和原更新时间。
- 使用现有 UBAAPlus 认证流程进行了 WebVPN 只读核对：流量接口可用；校园卡页面所引用的两个脚本地址返回 HTML，尚未验证头像、卡状态或流水接口，暂不新增推测字段。保留余额和官方网页入口。

本次最终验证：833 项测试，821 通过、12 跳过、0 失败；spotlessCheck、Debug/Release（ABI 拆包）构建和 arm64 两类 APK 签名验证通过。jsoup 的可选 RE2/J 未打包，保留其运行时检测及系统正则回退，使用两条精确的 R8 dontwarn 规则。未进行 Android 设备视觉验收，未推送、未移动标签。

## 主页与个人中心调整（2026-11-18，本地改动）

- 对照 UBAA 的 `shell_sync.dart` 与 `shared/sync_status.dart`，主页标题统一为「主页」，右侧 16dp 细线转圈反映认证恢复及主页实际读取；下拉刷新期间不重复显示标题转圈。
- 今日最后一项课程结束满一小时后显示明日课程，按明日日期匹配真实教学周并保留离线课表回退；未知结束时间或无课程时不猜测切换点。明日课程不匹配今日考勤，签到按钮禁用，课程详情使用明日日期。
- 姓名、学院和学生类型左对齐，学生类型映射为中文；头像与文字组居中对齐，余额卡收紧高度，标题和眼睛同排，数值与详情入口共用对齐线。
- 再次沿既有 WebVPN 认证流程只读核对 UC userinfo：实际返回的八个字段不含头像。按后续用户选择移除本机头像入口，仅继续调查学校头像来源，未取得照片时保留姓名头像。
- SRun 用量卡片与 zfw 账户流量重复，移除 SRun 卡片，只把同账户的在线 IP 作为可选补充。
- 深色提高背景与卡片明度，浅色收住高亮白底，共用主题层为卡片加入适量主题色；动态壁纸配色也采用一致表面层级。保留液态玻璃导航与磨砂内容，不增加高光框。

本轮验证：839 项测试，827 通过、12 跳过、0 失败；spotlessCheck、Debug/Release（ABI 拆包）构建和 arm64 APK 签名验证通过。配色测试覆盖深浅模式、常用配色与黑白自定义色极值，正文和次要文本达到 4.5:1；日期测试覆盖最后一节结束满一小时、未知时间、跨年与周日跨周。设备上的观感、字号缩放和系统选图流程仍待真机验收；未打标签、未推送。

## 学校头像与校园卡消费（2026-11-19，本地改动）

- 根据用户选择移除本机选图入口及专用缩略图存储，不回退到本机照片。沿校园门户前端发现 `/personal/frontend/data/info` 的 `d.info.avatar`，先核对 `xgh` 与当前账户一致，再下载同源 HTTPS 图片；真实账号已验证取得可解码图片。复用账号隔离的加密业务缓存，失败保留同账户的最近成功头像，未取得图片则显示姓名缩写。图片请求关闭 URL 日志。
- 沿校园支付平台的校园卡「流水」入口，定位 `mall.cc-pay.cn/api/campus_card/trades`，参数为 `stuNo`、`tradeType=consume`、`minTsCreation`、`maxTsCreation`、`pageSize` 和 `pageNum`。只查询当前已登录账户，不增加支付或卡状态写操作。
- 消费查询直接位于原校园卡服务页下方，不新增入口或栏目切换。两个并排日期框以「－」连接，默认今天单日；未来日期、倒置范围在日历中禁选，ViewModel 与 API 再校验。北京时间首日 00:00:00 至末日 23:59:59.999 转成 UTC 参数。
- 接口金额和余额以分计，使用十进制转换；实际消费金额为负，保留学校返回的符号。按日期及时间从旧到新排序，每天一个标题，每笔一张磨砂卡片，保留内容相同的独立记录。
- 实测分页总数可为 0，即使存在记录；因此依实际页大小读取到短页，检测重复页并限制最大读取页数。分页失败不写入不完整缓存，按账户和精确日期范围回退最近完整结果，保留原同步时间并提示更新失败。
- 两条实际读取链路及不同分页均已验证；测试仅保存合成数据，临时认证脚本及响应已移除。未执行充值、挂失等写操作。设备端观感仍需真机验收。

本轮最终验证：848 项测试，836 通过、12 跳过、0 失败；spotlessCheck、Debug/Release ABI 拆包构建及 arm64 APK 签名验证通过。合成测试覆盖头像账户核对与同源限制、HTML 伪图片拒绝、日期禁选和提交校验、同日完整 UTC 边界、分页总数异常、重复页及中途失败缓存回退、相同独立消费保留。两条实际只读接口和分页已核实；界面布局仍需真机确认。未打标签、未推送。

- 设置页最底栏标题从「功能选项」改为「其他选项」，开关文字仍是「？！！？」，免责声明与自动抢课/抢场地限制不变。

- 博雅详情的课程简介保留正文与图片顺序；图片按卡片内容宽度铺满，保留原始比例，不裁切。加载失败可重试，基本信息标题行提供复制图标。

### 本轮设置与个人资料调整

- 对话框确认统一使用 `UbaaConfirmAction` 的 ✓；关闭为 ×，保留具体动作的说明、长按提示、原事件及禁用条件。页面内明确标注“确认预约”的按钮同样改为 ✓。
- 个人资料手机号前 2/后 2 位、证件号前 2/后 1 位、银行卡前 4/后 4 位可见，其余遮挡；短值全部遮挡。学院和学生类型采用同行圆角标签，空间不足时自然换行。
- 设置收为外观、功能与提醒、桌面小组件、连接与数据、其他选项五组；宿舍和诊断按需展开。宿舍列表仅在展开时请求。
- 材质参数均为 0–100，支持草稿预览、重置、✓ 应用和 × 放弃，按应用外观偏好持久化。仅调节材质底色及边缘，不改变文字/图片颜色，不影响导航玻璃与弹窗。

### 空教室与研讨室时间轴

- 空教室在有“主楼”的结果中默认选择主楼；没有时展示该校区全部楼栋。日期/校区切换恢复默认，用户主动清除筛选后刷新不会覆盖选择。修正按楼栋名称搜索时出现空结果组的问题。
- 移除结果区楼栋标签、表格边框与单元格方块。表头为“节次”及 1–14 圆形序号；连续空闲节次合为圆角条，未列为空闲的节次保留低对比轨道和文字图例。
- 研讨室复用时间条，保留实际起止时间，已选为主题色加 ✓。名称列固定，所有时间行共享横向滚动位置，字体放大时扩大列宽。
- 研讨室时间间隔不合并，UI 点击仍使用原 spaceId/timeId；原有可选条件、同房间最多两个相邻时段及提交逻辑不变。
